kabakaba — Connexion vendeur
Interface mobile réservée aux gérants de cantine. Le compte est créé exclusivement par l'équipe kabakaba depuis l'outil web ; le vendeur ne s'inscrit jamais lui-même. Deux parcours ci-dessous : la première connexion (identifiants fournis) et la reconnexion (code PIN).
1Flux 1 — Première connexion
Le vendeur reçoit son numéro et un mot de passe temporaire de la part de l'équipe kabakaba (SMS ou appel). Il les saisit, confirme par OTP, puis remplace le mot de passe par un code PIN à 4 chiffres qui deviendra son seul moyen de connexion.

kabakaba — Dashboard vendeur
Suite de la maquette : une fois connecté (téléphone + mot de passe temporaire + OTP + code PIN, ou PIN seul au retour), le vendeur arrive sur cette interface. Trois zones : Commandes (cœur du produit), Portefeuille, Profil. Design aligné sur le thème clair déjà utilisé côté étudiant après connexion.
1Commandes — nouvelles demandes
Onglet par défaut à l'ouverture de l'app. Le vendeur a 5 minutes pour accepter ou refuser (§4.3 du CDC) ; passé ce délai, la commande est auto-annulée côté étudiant. Le refus exige un motif — obligatoire, saisi ici via une feuille (sheet) qui s'ouvre par-dessus la commande.

6Statistiques — Mes ventes
Hors périmètre strict du cahier des charges (§9.4-9.7 réserve les analyses comparatives à l'outil web Admin/Supervision), mais utile au vendeur pour piloter sa propre activité. Volontairement limité aux données qu'il génère lui-même — aucune comparaison avec d'autres cantines, aucune note client (les avis restent internes à la Supervision, §4.6). À valider avec toi avant développement : c'est un ajout de périmètre, pas une fonctionnalité actuellement spécifiée.
